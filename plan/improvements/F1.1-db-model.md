**Цель**: добавить модель `SignalOutcome` и CRUD-методы в `storage/database.py`.

**Файлы**:

| Файл                  | Что делать                                          |
|-----------------------|-----------------------------------------------------|
| `storage/database.py` | новая модель `SignalOutcome` + 5 методов в `Database` |

**Пошагово**:

1. Добавить модель `SignalOutcome` после `ContextSnapshotModel`:
   ```python
   class SignalOutcome(Base):
       __tablename__ = "signal_outcomes"

       id = Column(Integer, primary_key=True, autoincrement=True)
       signal_id = Column(
           Integer, ForeignKey("signals.id"), nullable=False, index=True
       )
       status = Column(String(20), nullable=False, default="OPEN")
       # OPEN / HIT_TP / HIT_SL / EXPIRED / MANUAL_CLOSE
       closed_at = Column(DateTime, nullable=True)
       close_price = Column(Float, nullable=True)
       pnl_pct = Column(Float, nullable=True)
       checked_at = Column(DateTime, default=lambda: datetime.now(timezone.utc))
   ```

2. Добавить методы в `Database`:
   - `get_signal(signal_id)` — получить сигнал по ID (нужен outcome_tracker)
   - `create_outcome(signal_id)` — создать OPEN outcome
   - `get_open_outcomes()` — список всех OPEN outcome
   - `close_outcome(outcome_id, status, close_price, pnl_pct)` — закрыть outcome
   - `get_outcome_stats()` — агрегация: closed, open, wins, avg_pnl, best, worst

3. `Base.metadata.create_all` автоматически создаст таблицу при `db.init()`.

**Edge cases**:
- `get_signal` — может вернуть `None` если сигнал удалён из `signals`.
- `close_outcome` — `scalar_one()` упадёт если outcome уже закрыт. Вызывающий должен фильтровать `status == "OPEN"`.
- `get_outcome_stats` — пустые списки → `avg_pnl=0.0`, `best_pnl=0.0`, `worst_pnl=0.0`.

**Готовность**:
- `pytest tests/test_database.py -v` — новые тесты проходят.
- `pytest -v` — все существующие тесты зелёные.

**Тесты** (`tests/test_database.py`):
