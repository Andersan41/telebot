# F1.3: /stats команда + связка signal→outcome при публикации

> **Статус**: 🔴 не сделано
> **Приоритет**: 🟢 low — UI-уровень
> **Зависимости**: F1.1 (модель + CRUD), F1.2 (outcome tracker)

**Цель**: админ-команда `/stats` для просмотра статистики закрытых сигналов + автоматическое создание outcome при публикации.

**Файлы**:

| Файл                    | Что делать                                          |
|-------------------------|-----------------------------------------------------|
| `scheduler/scanner.py`  | `await db.create_outcome(saved_signal.id)` после save |
| `bot/admin.py`          | `stats_command` — admin-only команда                 |
| `bot/handlers.py`       | регистрация `CommandHandler("stats", stats_command)` |

**Пошагово**:

1. В `scheduler/scanner.py` после `saved_signal = await db.save_signal(...)`:
   ```python
   await db.create_outcome(saved_signal.id)
   ```

2. В `bot/admin.py` добавить:
   ```python
   @_admin_only
   async def stats_command(update: Update, context: ContextTypes.DEFAULT_TYPE) -> None:
       stats = await db.get_outcome_stats()
       total = stats["closed"] or 1
       win_rate = stats["wins"] / total * 100
       text = (
           f"📊 <b>Статистика сигналов</b>\n\n"
           f"Всего закрытых: <b>{stats['closed']}</b>\n"
           f"Открытых: <b>{stats['open']}</b>\n"
           f"Win rate: <b>{win_rate:.1f}%</b> ({stats['wins']}/{total})\n"
           f"Средний PnL: <b>{stats['avg_pnl']:.2f}%</b>\n"
           f"Лучший: <b>{stats['best_pnl']:.2f}%</b>\n"
           f"Худший: <b>{stats['worst_pnl']:.2f}%</b>"
       )
       await update.message.reply_text(text, parse_mode=ParseMode.HTML)
   ```

3. В `bot/handlers.py` импортировать и зарегистрировать handler.

**Edge cases**:
- `/stats` без данных → closed=0, win_rate=0%, все PnL=0.00%
- HTML-экранирование: `stats` значения — float, не содержат `<`/`>`, но `html.escape` на строковых полях если будут
- `_admin_only` декоратор в `bot/handlers.py` vs `_ensure_admin` в `bot/admin.py` — использовать `@_admin_only` из handlers для консистентности с другими командами

**Готовность**:
- `/stats` в Telegram возвращает осмысленные числа при наличии закрытых сигналов
- При отсутствии данных — не падает с делением на ноль
- `pytest -v` — все зелёные

**Тесты**:
- `bot/admin.py` — тест `stats_command` с моком `db.get_outcome_stats`
  - empty stats → win_rate=0%, avg_pnl=0.0
  - mixed stats → correct win_rate, avg_pnl
