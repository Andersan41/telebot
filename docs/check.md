# check.md

# Промпт для проверки параметров сигналов крипто-бота

## Цель

Этот промпт предназначен для аудита торгового бота:

- проверки логики генерации сигналов;
- выявления ложных входов;
- проверки корректности EMA/RSI/OB/Volume/FVG/SMC параметров;
- определения переоптимизации;
- анализа фильтров;
- проверки качества risk-management;
- поиска конфликтующих условий;
- выявления задержек подтверждения сигнала;
- анализа производительности стратегии.

---

# Главный промпт

```text
Ты — senior quantitative crypto analyst и senior Python algo-trading engineer.

Твоя задача:

Провести полный технический аудит торгового крипто-бота.

Не давай поверхностный ответ.

Нужно:

1. Проанализировать:
- архитектуру стратегии;
- параметры индикаторов;
- качество фильтрации;
- качество сигналов;
- устойчивость логики;
- риск переоптимизации;
- вероятность repaint;
- задержки подтверждения;
- конфликтующие условия;
- слабые места;
- потенциальные false positive сигналы.

2. Проверить:
- EMA;
- RSI;
- MACD;
- Volume;
- ATR;
- OB;
- FVG;
- Liquidity;
- SMC;
- BOS;
- CHoCH;
- divergence;
- trend filters;
- volatility filters.

3. Определить:
- насколько параметры подходят под текущий рынок;
- есть ли lagging indicators;
- есть ли избыточные фильтры;
- есть ли недостаток подтверждений;
- где бот теряет лучшие входы;
- где бот ловит шум;
- где возникает late entry.

4. Проверить риск-менеджмент:
- SL;
- TP;
- trailing;
- break-even;
- dynamic stop;
- volatility adaptation.

5. Проверить качество multi-timeframe анализа.

6. Проверить:
- race conditions;
- async ошибки;
- network retry logic;
- rate limit handling;
- websocket stability;
- reconnect logic;
- memory leaks;
- asyncio проблемы;
- aiohttp bottlenecks.

7. Проверить качество кода:
- производительность;
- архитектуру;
- потенциальные баги;
- опасные места;
- блокировки event loop;
- excessive API calls;
- неэффективные запросы.

8. Дать:
- подробный разбор;
- слабые места;
- что исправить;
- как улучшить winrate;
- как уменьшить false signals;
- как уменьшить drawdown;
- как улучшить RR;
- какие параметры оптимизировать;
- какие параметры опасны;
- какие фильтры лишние;
- какие фильтры стоит добавить.

9. Выдать:
- конкретные рекомендации;
- улучшенные параметры;
- улучшенную архитектуру;
- improved signal logic;
- рекомендации для scalp/intraday;
- рекомендации для volatile market;
- рекомендации для ranging market.

10. После анализа:

Составь:
- список критических ошибок;
- список средних проблем;
- список minor issues;
- roadmap улучшений;
- priority fixes.

Формат ответа:

- максимально технический;
- без воды;
- с примерами;
- с объяснением почему это проблема;
- с примерами улучшений.
```

# Дополнительный промпт для проверки качества сигналов

```text
Проанализируй только качество сигналов.

Определи:

- насколько сигналы запаздывают;
- есть ли входы в ликвидность;
- есть ли входы перед sweep;
- есть ли подтверждение объема;
- есть ли фильтрация флэта;
- есть ли защита от low liquidity;
- есть ли защита от news volatility;
- где возникают false breakout;
- где бот входит слишком поздно;
- где бот пропускает лучшие входы.
```

# Финальная цель

После проверки бот должен:

- уменьшить false signals;
- улучшить timing;
- уменьшить drawdown;
- стабилизировать RR;
- лучше работать в volatility;
- корректно переживать news spikes;
- не перегружать API;
- стабильно работать async.
