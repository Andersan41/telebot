## ВОПРОС 1: Кто генерирует направление сигнала (BUY/SELL/NO_SIGNAL)?

**Ответ: `signal_engine.evaluate()` — единственный генератор направления. `confidence_v2` НЕ изменяет и НЕ отменяет направление.**

### Точная последовательность вызовов в `scanner.py`:

```
scan_symbol() [строка 255]
  │
  ├── Шаг 1: _get_indicators() [строка 266] → ind, df
  ├── _detect_regime() [строка 272] → regime
  ├── Ранний liquidity/structure анализ [строки 279-286]
  ├── Pre-MTF check [строки 288-305]
  ├── Confirmation on 15M [строки 308-334] → entry_price
  │
  ├── ★ signal_engine.evaluate() [строка 336] → result (направление зафиксировано)
  │     └── Внутри: direction определяется на строках 340-372
  │     └── Возвращает SignalType.BUY / SELL / NO_SIGNAL [строка 661]
  │
  ├── result.is_actionable проверка [строка 346] → если NO_SIGNAL, выход
  │
  ├── ... 15+ gate/filter проверок [строки 362-997] ...
  │
  ├── confidence_engine_v2.compute() [строка 1063] → ОЦЕНИВАЕТ, не меняет
  │     └── result._confidence_v2 = conf_v2 [строка 1092]
  │
  ├── Дедупликация [строки 1098-1125]
  ├── Сохранение в БД [строка 1128]
  └── notify_callback(result, context_verdict) [строка 1169] → Telegram
```

### Код-доказательство:

**Направление определяется в `signal_engine.py:339-372`:**

```python
# signal_engine.py:339-372
direction = None
if has_leading_trigger:
    if leading_trigger_direction:
        direction = "buy" if leading_trigger_direction == "bullish" else "sell"
    ...
if direction is None:
    ema_direction = "buy" if ind.ema_fast > ind.ema_slow else "sell"
    ...
    direction = ema_direction
```

**Направление фиксируется как SignalType на строке 661:**

```python
# signal_engine.py:661
signal_type = SignalType.BUY if direction == "buy" else SignalType.SELL
```

**confidence_v2 вызывается ПОСЛЕ фиксации направления, в `scanner.py:1063-1092`:**

```python
# scanner.py:1063-1092
conf_v2 = confidence_engine_v2.compute(
    direction=direction_v2,  # direction_v2 = result.signal.value (строка 1025)
    ...

result._confidence_v2 = conf_v2  # только записывает результат, не меняет result.signal
```

**В `confidence_v2.py:71-125` — `compute()` возвращает `ConfidenceResult` с полем `recommendation` (строка 124), но это поле НЕ используется scanner.py для изменения направления.** Scanner.py только присваивает результат в `result._confidence_v2` (строка 1092) и логирует (строки 1093-1096).

### Уровень 3: Context verdict (отдельная система)

**`context/scorer.py:160-167`** — генерирует вердикт CONFIRMED/WEAK/CONFLICTED/BLOCKED. Это **НЕ confidence_v2**, а `context_scorer`. Он блокирует через scanner.py строки 824-847.

### Ключевой вопрос: signal_engine=BUY + confidence_v2=WEAK → что происходит?

**Сигнал ИДЁТ.** Confidence_v2 не имеет gate-права. Вот цепочка:

1. `signal_engine.evaluate()` возвращает `SignalType.BUY` (строка 661)
2. `result.is_actionable` = True (строка 66-67) → не выходим
3. Все post-signal gates в scanner.py проходят
4. `confidence_engine_v2.compute()` на строке 1063 возвращает `ConfidenceResult(quality="weak")`
5. Это записывается в `result._confidence_v2` (строка 1092)
6. Далее идёт дедупликация → сохранение → отправка

**Но!** Dynamic risk на строке 1000 берёт `setup_quality = result.verdict.lower()`. Если verdict="СЛАБЫЙ" (из signal_engine, строки 76-84) → setup_quality="weak" → `calculate_risk()` возвращает `should_trade=False` (dynamic_risk.py:54-56) если `risk_weak_trade=false` (по умолчанию). Это блокирует на строке 1013-1022.

**Итог: signal_engine=BUY + confidence_v2=WEAK → dynamic risk блокирует (если risk_weak_trade=false). Но блокирует НЕ confidence_v2, а signal_engine's own verdict (score < 4 → "СЛАБЫЙ").**

## ВОПРОС 3: Кто и как рассчитывает размер позиции (risk sizing)?

**Ответ: `risk/dynamic_risk.py:calculate_risk()`. Зависит от `signal_engine` verdict (НЕ confidence_v2), volatility regime и BTC/ETH alignment.**

### Формула расчёта:

**`dynamic_risk.py:46-51`:**

```python
@property
def effective_risk_pct(self) -> float:
    return round(
        self.base_risk_pct * self.volatility_multiplier * self.correlation_multiplier,
        4,
    )
```

### Параметры формулы:

**1. `base_risk_pct` — из `dynamic_risk.py:60-67`:**

```python
def _base_risk_for_quality(quality: str) -> float:
    if quality == "strong":
        return settings.config.risk.risk_strong_pct      # default 1.0%
    elif quality == "moderate":
        return settings.config.risk.risk_moderate_pct    # default 0.5%
    elif quality == "weak":
        return settings.config.risk.risk_weak_pct        # default 0.25%
    return 0.0
```

**2. `volatility_multiplier` — из `dynamic_risk.py:70-73`:**

```python
def _volatility_multiplier(volatility_regime: str) -> float:
    if volatility_regime == "high":
        return settings.config.risk.volatility_high_multiplier  # default 0.5
    return 1.0
```

**3. `correlation_multiplier` — из `dynamic_risk.py:76-82`:**

```python
def _correlation_multiplier(btc_aligned=True, eth_aligned=True) -> float:
    if not btc_aligned or not eth_aligned:
        return settings.config.risk.correlation_misaligned_multiplier  # default 0.5
    return 1.0
```

**4. `setup_quality` берётся из `result.verdict` (signal_engine), НЕ из confidence_v2.**

**`scanner.py:1000`:**

```python
setup_quality = result.verdict.lower() if result.verdict.lower() in ("strong", "moderate", "weak") else "moderate"
```

**`signal_engine.py:70-84`** — verdict формируется по score:

```python
@property
def verdict(self) -> str:
    if self._regime_blocked:
        return "ЗАБЛОКИРОВАН"
    if self._confidence_v2 is not None:
        q = self._confidence_v2.quality
        return {"strong": "СИЛЬНЫЙ", "moderate": "УМЕРЕННЫЙ", "weak": "СЛАБЫЙ"}.get(q, "СЛАБЫЙ")
    s = self.score
    if s >= 6:
        return "СИЛЬНЫЙ"
    elif s >= 4:
        return "УМЕРЕННЫЙ"
    elif s >= 2:
        return "СЛАБЫЙ"
    else:
        return "ОЧЕНЬ СЛАБЫЙ"
```

**Важно:** verdict на строках 73-75 **использует confidence_v2.quality если `_confidence_v2 is not None`**. Но `_confidence_v2` в `signal_engine.evaluate()` создаётся с quality на основе `score` (строка 724: `quality="strong" if score >= 6 else "moderate" if score >= 4 else "weak"`), а потом в scanner.py перезаписывается результатом `confidence_engine_v2.compute()` (строка 1092). Получается, verdict в scanner.py уже отражает 10-factor confidence_v2 quality.

**Но в scanner.py:1000** `setup_quality` берётся ДО перезаписи confidence_v2 (вызов `result.verdict` читает `_confidence_v2`, который уже установлен на строке 1092). Порядок:

- Строка 1000: `setup_quality = result.verdict.lower()` — `_confidence_v2` уже установлен (строка 1092)
- Строка 1001-1006: `calculate_risk(setup_quality=setup_quality, ...)`

**Итог: размер позиции ЗАВИСИТ от confidence_v2 quality, потому что verdict использует confidence_v2.quality.** Пример:

- confidence_v2.quality="weak" → verdict="СЛАБЫЙ" → setup_quality="weak" → base_risk=0.25%
- effective_risk = 0.25% × vol_mult × corr_mult

**Блокировка:** если `dynamic_risk_enabled=True` и `risk_weak_trade=False` (default) → weak setups блокируются на строке 1013.

## ВОПРОС 4: Что видит трейдер в Telegram-сообщении?

**Ответ: Да, показывается verdict + confidence + quality. Это информационный элемент — бот уже принял решение.**

### Шаблон сообщения — `signal_engine.py:100-181`:

```python
# signal_engine.py:100-181 (ключевые строки)
def format_message(self) -> str:
    header = f"{self.signal.value} — {signal_word}"  # "BUY — ПОКУПКА"
    lines = [
        header,
        f"Инструмент: {self.symbol}",
        f"Таймфрейм: {self.timeframe.upper()}",  # + confirmation TF
        f"Цена входа: {entry}",
        f"\U0001f534 Stop Loss: {self.sl} ({sl_pct:+.2f}%)",
        f"\U0001f7e2 Take Profit: {self.tp} ({tp_pct:+.2f}%)",
        f"R/R: 1:{rr:.1f}",
        f"\nТехнические факторы ({self.score}/7):",  # ← score/7
        f"\nРыночный контекст:",                       # ← context items
        f"\nПредупреждения:",                          # ← warnings
        f"\nРежим: {regime_display}",
        f"\nИтог: {self.verdict} | Уверенность: {self.confidence:.1f}%",  # ← verdict + confidence
    ]
    if self._confidence_v2 is not None:
        lines.append(f"Качество: {q}")  # ← quality из confidence_v2
```

## ВОПРОС 5: Используется ли confidence в cooldown или outcome tracking?

### Cooldown:

**Нет. Cooldown НЕ учитывает confidence.**

**`scanner.py:215-226`:**

```python
async def _is_cooldown_active(symbol: str, timeframe: str) -> bool:
    last = await db.get_cooldown(symbol, timeframe)
    if last is None:
        return False
    delta = datetime.now(timezone.utc) - last
    return delta < timedelta(minutes=config.signal_cooldown_minutes)  # default 45 min

async def _set_cooldown(symbol: str, timeframe: str) -> None:
    await db.set_cooldown(symbol, timeframe, datetime.now(timezone.utc))
```

**Дедупликация на строках 1098-1125** — тоже без учёта confidence. Проверяется только направление и время.

### Outcome tracking:

**Нет. Outcome tracker НЕ разбивает по confidence.**

**`outcome_tracker.py:25-88`:**

```python
async def check_open_outcomes() -> None:
    outcomes = await db.get_open_outcomes()
    for outcome in outcomes:
        signal = await db.get_signal(outcome.signal_id)
        # ... проверяет TP/SL по цене ...
        if hit_tp:
            await db.close_outcome(outcome.id, "HIT_TP", current, pnl)
        elif hit_sl:
            await db.close_outcome(outcome.id, "HIT_SL", current, pnl)
```

**В БД сохраняется `factor_fingerprint`** (scanner.py:1138) — строка из активных факторов. Это позволяет искать исторический winrate по комбинации факторов (scanner.py:1052-1061). Но это **fingerprint factor combination, а НЕ confidence level (strong/moderate/weak)**.

**`scanner.py:1052-1061`:**

```python
historical_wr = await db.get_historical_winrate(factor_fingerprint)
```

### Важный аналитический слой для сохранения:

**`_build_factor_fingerprint()` (scanner.py:52-139)** — генерирует детерминированную строку из factor strengths. Это ключ к historical winrate blending в confidence_v2 (confidence_v2.py:108-116). При рефакторинге этот механизм нужно сохранить — он связывает outcome результаты с текущей оценкой confidence.

### Роли по схеме:

| Компонент | Роль | Может блокировать? |
|-----------|------|-------------------|
| `signal_engine` | **Генератор** направления + 7 tech factors + SL/TP | Да (11 gate-ов) |
| `context_scorer` | **Фильтр** по рыночному контексту (6 factors) | Да (BLOCKED / MIN_VERDICT) |
| `scanner.py` gates | **Фильтр** (15+ проверок) | Да (все gate-ы) |
| `confidence_v2` | **Аналитик** (10 factors, blended winrate) | **НЕТ** — только оценивает |
| `dynamic_risk` | **Sizing** + слабые setup blocking | Да (should_trade) |
| `outcome_tracker` | **Трекер** SL/TP результатов | Нет (read-only) |
