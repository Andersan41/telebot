# Core Strategy — Architectural Principles

## Принцип №1: Бот ищет структуру рынка, а не индикаторы.

Источник сигнала — не EMA, не RSI, не MACD.

Источник сигнала — то, как цена взаимодействует с ликвидностью:

- Break of Structure (BOS)
- Change of Character (CHoCH)
- Liquidity Sweep
- Order Block / Fair Value Gap

Индикаторы (EMA, RSI, MACD, Supertrend) — это **описание**, а не **причина**.
Они не создают edge. Они подтверждают или опровергают структурный сетап.

---

## Принцип №2: Каждый Information Source обязан приносить НОВУЮ информацию.

Если два источника отвечают на один вопрос — один из них лишний.

| Вопрос | Ответ | Information Source |
|--------|-------|--------------------|
| Есть ли структура? | BOS / CHoCH / Sweep | Market Structure |
| Есть ли зона входа? | OB / FVG | Liquidity Zones |
| Подтверждает ли тренд? | HTF alignment | Higher Timeframe |
| Есть ли участие? | Volume above avg | Volume |
| Какой RR? | Entry → SL → TP | Risk Geometry |
| Можно ли торговать? | ATR, R:R, portfolio | Risk Gate |

Всё остальное — **дублирует** один из этих вопросов.

## Принцип №3: Gate не имеет права существовать, если его удаление улучшает expectancy.

Не WR. Не PF. А **ожидаемая доходность в R после издержек**.

```
Expectancy = (WR × AvgWin) - ((1 - WR) × AvgLoss) - Costs
```

Каждый gate измеряется не «сколько блокирует», а **сколько денег забирает**.

---

## Принцип №4: ML никогда не создаёт信号. Он только оценивает вероятность.

ML-модель не решает «войти или нет».
Она отвечает на вопрос: «Какова P(TP) для этого сетапа при текущих условиях?»

Решение о входе принимает **ядро** (Market Structure → Liquidity → Execution → Risk).
ML — это **калибровщик**, а не **фильтр**.

---

## Принцип №5: Любое усложнение требует доказательства.

Добавление нового gate / information source / фильтра требует:

1. Гипотеза: «Это увеличит expectancy на N%»
2. Тест: Shadow Mode, 2-4 недели, одинаковые рыночные условия
3. Результат: expectancy вырос → оставляем. Не вырос → удаляем.

Без доказательств — без изменений.

---

## Принцип №6: Архитектура ядра — 5 фаз.

```
1. Market Structure    → Есть ли тренд? (BOS/CHoCH)
2. Liquidity Event     → Есть ли зона входа? (Sweep/OB/FVG)
3. Execution Window    → Подтверждает ли контекст? (HTF, Volume)
4. Risk Check          → Допустим ли риск? (RR, SL, Portfolio)
5. Send                → Публикация сигнала
```

Не 32 gate. Не 17 gate. **5 фаз.**

Каждая фаза — один вопрос. Один ответ. Одно решение.
