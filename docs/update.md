ЗАДАЧА 1. Унифицировать точку отсчёта SL/TP

Найди функцию:
_calculate_sl_tp(...)

Измени её сигнатуру так, чтобы она принимала:
entry: float

Все формулы внутри функции должны использовать именно entry вместо close текущего таймфрейма.

Требование:
- SL считается относительно entry
- TP считается относительно entry
- ATR fallback остаётся прежним
- логика BOS сохраняется

После этого найди все вызовы функции и обнови их.
Особенно проверь scanner.py: entry_price должен вычисляться ДО вызова _calculate_sl_tp().

ЗАДАЧА 2. Подключить structural SL

Сейчас используется:
calculate_structural_tp(...)

Найди место его вызова.
Добавь перед ним вызов:
calculate_structural_sl(...)

Порядок должен быть:
base ATR/BOS SL+TP
↓
structural SL
↓
structural TP
↓
валидации

Требование:
Structural SL может заменить базовый только если он улучшает риск.

Для BUY:
distance(structural_sl) <= distance(current_sl)

Для SELL аналогично.

Если structural SL дальше текущего стопа и ухудшает RR — не использовать его.

Добавь логирование:
- structural SL accepted
- structural SL rejected (worse risk)

ВАЖНО: BOS-логика в _calculate_sl_tp уже применяет буфер 0.5% к уровню BOS 
(bos_level * 0.995 для BUY, bos_level * 1.005 для SELL). Когда разбираешься, как 
calculate_structural_sl встраивается в пайплайн, явно проверь и опиши в отчёте: 
если сигнал уже прошёл через BOS-ветку (и SL уже привязан к структуре с буфером), 
должна ли calculate_structural_sl вообще пытаться её переопределить, или она должна 
применяться только к ATR-based SL (когда BOS не сработал)? Прими решение исходя из 
того, что не должно быть двойного наложения буферов на один и тот же уровень, и 
зафиксируй это решение явно в отчёте с обоснованием.

ЗАДАЧА 3. Ограничение минимального и максимального стопа

Добавь новые параметры конфига:
min_sl_distance_pct = 1.0
max_sl_distance_pct = 10.0

После определения финального SL вычисляй:
sl_distance_pct = abs(entry - sl) / entry * 100

Если sl_distance_pct < min_sl_distance_pct — сдвигай стоп до минимально допустимого 
расстояния.

Если sl_distance_pct > max_sl_distance_pct — НЕ обрезай стоп. Сигнал должен быть отклонён.
Используй существующий механизм reject.

Лог: rejected: SL distance 12.4% exceeds max 10.0%

ЗАДАЧА 4. Финальная проверка RR

Добавь новый параметр:
min_rr_threshold = 1.5

После того как SL и TP окончательно сформированы:
rr = abs(tp - entry) / abs(entry - sl)

Если rr < min_rr_threshold — сигнал должен быть отклонён.
Используй существующий механизм reject.

Лог: rejected: RR 1.23 below threshold 1.50

Важно: проверка должна происходить ПОСЛЕ ATR/BOS логики, structural SL, structural TP 
и всех корректировок стопа (включая buffer из задачи 6 и пороги из задачи 3). То есть 
проверяется финальный RR реальной сделки.

ЗАДАЧА 6. Stop Hunt Buffer

Добавь новый параметр:

Если используется structural SL на основе liquidity sweep, sweep low/high, order block 
level — то стоп должен ставиться не на уровень, а за уровень.

Для BUY: sl = structural_level * (1 - buffer_pct/100)
Для SELL: sl = structural_level * (1 + buffer_pct/100)

Применять только к structural SL (результат calculate_structural_sl), НЕ к BOS-based SL 
из _calculate_sl_tp — он уже имеет собственный буфер 0.5%, см. примечание в задаче 2.
